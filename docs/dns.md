# 解析与加密 DNS

## 上游服务器

在“DNS 设置 → 上游服务器”里配置，每行一个地址，最多 32 个。支持的格式：

| 类型 | 写法 |
| --- | --- |
| 普通 DNS | `1.1.1.1:53`（只写 IP 时默认 53 端口） |
| DoT | `tls://dns.example:853` |
| DoH（HTTP/2） | `https://dns.example/dns-query` |
| DoH3（HTTP/3） | `h3://dns.example/dns-query` |
| DoQ | `quic://dns.example:853` |
| DNSCrypt | `sdns://…`（也支持 `sdns+udp://`、`sdns+tcp://`），服务会验证 Provider 证书 |

- **备用上游**：只在主上游全部失败、超时或返回 SERVFAIL / REFUSED 时才使用，不参与主上游的分发。
- **Bootstrap DNS**：解析加密上游（如 `tls://dns.example`）的域名时使用的普通 DNS，建议填 IP。
- **超时**：单个上游的连接和查询超时（默认 4 秒）。
- **测试上游**：逐个测试当前文本框里的地址，显示协议、耗时或错误，测试不写入缓存。

### 请求分发策略

| 策略 | 说明 |
| --- | --- |
| 负载均衡（默认） | 按健康状态轮转，失败时自动换下一个，额外流量最少 |
| 并行请求 | 同时询问多个上游，采用第一个有效应答；更快也更容错，但请求量成倍增加 |
| 最快 IP 地址 | 并发查询后，对应答里的公网地址做 TCP/443 连接测速，把最快的地址排在前面。测速发生在服务器上，结果不代表客户端的速度，只适合明确需要多线路优化的场景，并会增加额外流量 |

### 健康检查与熔断

连续失败 3 次的上游会被暂时跳过（冷却 30 秒起，指数退避，最长 5 分钟）；所有上游都在冷却时，只放行一个探测请求，避免同时冲击。每个上游最近 30 分钟的延迟和失败情况显示在仪表盘上。

## 域名分流

让指定域名（含子域名）使用**专属上游**，典型用途：内网域名交给路由器或公司 DNS，其余走公共加密上游。

![域名分流](images/routes.png)

```yaml
dns:
  upstream_routes:
    - name: 公司内网
      domains: [corp.example.com, 10.in-addr.arpa]
      upstreams: ["10.0.0.1:53"]
```

- 域名匹配**最具体的一条**；同一个域名不能出现在两条分流里。
- **分流的域名只会发给它的专属上游**，失败时不会回退到默认上游或备用上游（客户端得到 SERVFAIL），以免把内部域名泄露给公共解析器。
- 分流域名视为可信：不受 DNS Rebinding 防护影响（内网域名返回私网地址是正常的），也不做本地 DNSSEC 验证。
- 可以分流反向解析区（如 `10.in-addr.arpa`），配合“私网反向解析”使用。
- 每条分流最多 64 个域名、8 个上游；总共最多 64 条。分流的上游健康状态和延迟趋势显示在分流卡片里。

## 本地记录

在“本地记录”页维护 A、AAAA、CNAME、TXT 记录，优先于缓存和上游（过滤规则仍然先生效）。

- 同一个域名可以有多条记录；TTL 默认 300 秒，最大 86400 秒。
- **A / AAAA 记录会自动生成 PTR 记录**：把 `nas.home.arpa` 指向 `192.168.1.10` 后，查询 `10.1.168.192.in-addr.arpa` 会得到 `nas.home.arpa`。

## 解析行为

- **私网反向解析（默认开启）**：私网地址（10.x、172.16–31.x、192.168.x、169.254.x、127.x、fc00::/7、fe80::/10）的反向查询由本机应答——匹配本地记录的返回主机名，其余返回 NXDOMAIN，不再发往公共上游，避免泄露内网信息。已配置分流的反向区不受影响。
- **不解析 IPv6（AAAA）**：AAAA 查询直接返回空应答，不发往上游，适合没有 IPv6 出口的网络。本地记录里的 AAAA 仍会返回。

## 缓存

- 按**字节**计容量（默认 4 MB）的分片 LRU 缓存，支持负缓存（NXDOMAIN 等）。
- **TTL 下限 / 上限**：在写入缓存和第一次应答前统一限制 TTL，上限为 0 表示不限制。
- **乐观缓存**：条目过期后仍可短暂返回旧答案（TTL 用“乐观应答 TTL”，默认 30 秒），同时在后台刷新，最长保留“最大寿命”（默认 12 小时）。
- **预取**：被反复访问的条目在剩余 TTL 最后 20% 时于后台刷新，热门域名不会因过期而变慢；TTL 小于 10 秒的条目不预取。
- 带 ECS 的请求按规范化子网建立独立的缓存变体；带 Cookie、NSID、Padding 或未知 EDNS 选项的请求会绕过缓存。
- 并发的相同查询会合并成一次上游请求。

## DNSSEC

- **向上游请求 DNSSEC**：为没有带 DO 标志的请求补上，让上游返回签名数据。
- **本地验证**：用内置的 IANA 根信任锚（或你提供的 DNSKEY / 受控文件）验证签名链；验证失败（Bogus）的应答会作为错误处理。受控信任锚文件变更时自动验证并热重载；可选“自动更新根信任锚”。
- 验证结果（Secure / Insecure / Bogus / Indeterminate）的统计显示在仪表盘。

## 对外提供加密 DNS

在“服务设置 → 加密 DNS”启用后，DNSentry 自己也作为加密 DNS **服务器**：

| 协议 | 默认端口 | 说明 |
| --- | --- | --- |
| DoT | 853 | DNS over TLS |
| DoH | 443 | 路径 `/dns-query` |
| DoH3 | 443 | DNS over HTTP/3 |
| DoQ | 853 | DNS over QUIC |
| DNSCrypt v2 | 443 | 独立启用，运行后控制台显示可复制的 stamp |

- 每种协议最多 16 个监听地址，每行一个；监听地址为空表示不监听这个协议。
- **证书**：填证书和私钥的文件路径，或直接粘贴 PEM（粘贴的内容优先；私钥不会通过 API 返回）。
- DNSCrypt 的 Provider 密钥和 Resolver secret 首次启用时自动生成。
- 这些设置改动后都需要重启。
- **暴露到公网前**请先阅读 [SECURITY.md](../SECURITY.md)，务必设置客户端限制，避免成为开放解析器。

## 访问控制

在“服务设置 → 访问控制”里：

- **允许 / 拒绝的客户端**：IP 或 CIDR。拒绝列表优先于允许列表；允许列表留空表示允许所有。
- **单客户端限速**：每个来源地址每秒的查询数，0 表示不限。
- **最大并发查询**：超过返回 SERVFAIL（默认 2048）。
- **DNS Rebinding 防护**：阻止公网域名返回私网、回环或链路本地地址；可以为可信的内网域名设置例外。

这些都按**来源地址**起作用，用来限制“谁能使用这个 DNS”，而不是识别具体设备。
